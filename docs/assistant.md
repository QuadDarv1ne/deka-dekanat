# Локальный помощник

MiniCPM5-2B в Q4_K_M и llama.cpp. [Официальный GGUF OpenBMB](https://huggingface.co/openbmb/MiniCPM5-2B-GGUF) распространяется по Apache-2.0. Размер файла 1 561 318 368 байт. Ревизия, размер и SHA-256 закреплены в `infrastructure/assistant/model-manifest.json`.

## Docker

```powershell
.\deka.ps1 docker-demo
```

Модель включена по умолчанию. Сервис `model-init` загружает файл в `var/models`. Загрузка продолжается после обрыва, а готовый файл принимается только при совпадении размера и SHA-256. При повторном запуске проверенная модель используется без скачивания. Ошибка контрольной суммы блокирует запуск модели. Архив исходников не содержит GGUF и локальных настроек.

Запуск сначала проверяет GPU. Для NVIDIA используется CUDA-образ и явное разрешение GPU в Compose. На Linux с `/dev/dri` может использоваться Vulkan. После запуска проверяется готовность сервера модели. При недоступном GPU, ошибке старта или проверки готовности выполняется повторный запуск на CPU. Принудительно выбрать CPU можно параметром `-Acceleration cpu`, исключить помощника из запуска параметром `-WithoutAssistant`.

На Windows NVIDIA в Docker требует WSL2 и подходящего драйвера: [Docker GPU support](https://docs.docker.com/desktop/features/gpu/). В Linux для NVIDIA нужен настроенный NVIDIA Container Toolkit. Образы и параметры описаны в [документации llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/docs/docker.md). CPU, CUDA и Vulkan закреплены digest в Compose. Переопределения `LLAMA_IMAGE`, `LLAMA_CUDA_IMAGE`, `LLAMA_VULKAN_IMAGE` сохраняются. Полный запуск Docker Engine на этом компьютере не проверен.

Результат выбора записывается в `var/run/docker-acceleration.json`. Журнал неудачного GPU-запуска находится в `var/logs/docker-ai-gpu.log`. Самостоятельный запуск через `docker compose --profile ai up` скачивает модель, но использует CPU; автоматический выбор и переход выполняет `deka.ps1`.

## Windows без Docker

```powershell
.\deka.ps1 assistant
.\deka.ps1
```

При первом запуске скачиваются модель и проверенные бинарные файлы llama.cpp. Для GPU используется Vulkan, для резерва отдельная CPU-сборка. Подходящий дискретный GPU имеет приоритет перед встроенной графикой. Если GPU не найден или не запустился, используется CPU. На этом компьютере проверен запуск на NVIDIA GeForce RTX 5080.

Можно явно запустить `.\deka.ps1 -Acceleration cpu`. Выбор и PID находятся в `var/run/assistant-process.json`. Перед остановкой проверяются путь исполняемого файла и время создания процесса. Модель доступна только на `127.0.0.1:5188`. Настройки приложения находятся в `var/config/application.env`:

```dotenv
AI_BASE_URL=http://127.0.0.1:5188/v1
AI_MODEL=deka-assistant
```

## Поведение

История хранится отдельно для каждого пользователя. Ответ поступает через SSE. Можно остановить генерацию и продолжить разговор позже. Чаты из истории доступны для переименования и удаления; название ограничено 100 символами, а удаление вместе с чатом убирает все его сообщения. Сервер проверяет владельца чата, размер сообщения, Origin, частоту запросов и параллельные генерации.

Сервер выбирает разделы по вопросу: собственные оценки, заявления, посещаемость и готовность к аттестациям, расписание доступной группы, объявления факультета. Уточняющий вопрос может использовать тему предыдущих сообщений. Новый общий вопрос не вызывает загрузку личных записей. Количество записей и длина контекста ограничены; признак `hasMore` сообщает о сокращении. История разговора также ограничена по длине. Подпись "Данные для ответа" показывает переданные разделы, а не подтверждение каждого утверждения модели.

Для учебных вопросов о JOIN и const добавлены краткие справочные сведения из официальной документации PostgreSQL и MDN. Это небольшой справочник, а не поиск по университетским документам. Преподавателю передаётся доступное расписание. Сотрудникам не передаются списки чужих оценок. Пароли, сессии и параметры подключения в контекст не входят. Модель не имеет инструментов для изменения данных.

Обычные вопросы об учёбе, программировании, планировании и повседневной жизни разрешены. Поддерживаемые вопросы о текущем времени обрабатываются серверными часами до обращения к модели. Интернет-поиск не подключён; актуальные погода, новости и цены модели недоступны.

Прямой вопрос о ближайших занятиях или экзамене, готовых справках и пропусках получает ответ из записей текущего студента. В ответе есть ссылка на раздел источника. Это исправление по повторному прогону 18 ноября: модель ошибочно указала одну пару под двумя датами. Смешанные и учебные вопросы продолжают обрабатываться моделью.

## Результат проверки 17 ноября

На настоящей модели выполнены 30 вопросов через приложение: личные записи, отсутствие сведений, учебные темы, время и границы доступа. Транспортных ошибок не было. Автоматические проверки фраз лишь отмечают ответы для ручного просмотра. При чтении ответов обнаружены ошибочное объяснение const и вымышленные задания в плане подготовки. MiniCPM 2B не прошла проверку качества для самостоятельных рекомендаций в реальном вузе.

На RTX 5080 короткие ответы в отдельном сравнении достигали примерно 241-247 токенов/с, CPU с шестью потоками около 40 токенов/с. Это два коротких запроса, а не универсальный рейтинг производительности. Отчёты установки находятся в `var/reports/assistant-evaluation.json` и `model-runtime-check.json`.

Для следующего сравнения выбрана официальная Qwen3-8B Q4_K_M. Её загрузка в этом сеансе остановилась до завершения, поэтому она не установлена и улучшение качества не заявляется. Провайдер отделён от интерфейса и истории. Общий API-псевдоним `deka-assistant` позволяет менять модель без изменения клиентского кода. Нативный запуск сверяет модель в записи процесса, добавляет отсутствующие настройки и сохраняет существующие значения.

До пилота нужны проверка более сильной модели на том же наборе, вопросы конкретного вуза и оценка работы при отсутствии данных. Ответы требуют проверки по исходным записям.
