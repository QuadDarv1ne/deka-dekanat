# Проверка текущей версии

Дата: 18 ноября 2026. Сохранены прежние миграции; миграция 011 добавляет переписку в заявлении.

Последний полный прогон: 51 тест. Проверка Svelte и TypeScript завершилась без ошибок и предупреждений. Выполнена production-сборка. Резервная копия восстановлена в отдельную базу, контрольные количества записей совпали.

## Чистая установка

Архив исходников распакован в новую папку. PowerShell 7, Node.js 26.13.0 и PostgreSQL 18.6. Команда `setup` загрузила зависимости в пустой кеш npm и создала отдельную базу. Применены все 11 миграций. После `seed` серверная сборка открыла кабинет. Повторный запуск обнаружил уже работающий экземпляр, повторное наполнение сохранило существующие данные.

[Docker Compose v5.7.0](https://github.com/docker/compose/releases/tag/v5.7.0) проверил через `config --quiet` базовую конфигурацию и варианты CUDA и Vulkan. Сборка и запуск самих контейнеров требуют Docker Engine. На машине проверки выполнен нативный запуск.

## Автоматические проверки

`.\deka.ps1 check` проверяет Svelte, TypeScript и service worker. `.\deka.ps1 test` создаёт отдельную базу с уникальным именем, применяет миграции, наполняет её учебными данными и запускает production-сборку. После тестов удаляются только база этого прогона и его сборка. Файлы тестов выполняются последовательно из-за общей тестовой БД; гонки проверяются параллельными HTTP-запросами внутри соответствующих сценариев.

Покрываются четыре роли, личные данные и факультеты, сессии, Origin, весь путь заявления, QR, CSV/XLSX и атомарный откат, посещаемость, учебный план и календарь, очередь деканата, общая оболочка студента, протокол чата, ограничения ИИ и архитектурные границы.

Регрессии аудита: замена отменённой пары и запрет конфликтующего восстановления; устаревшая запись оценки и единственный победитель гонки; история значений; конфликт после предпросмотра импорта; отзыв назначения; неизменяемость аудита ролью приложения; отсутствие сертификата для общего обращения. Для переписки проверяются запреты чтения и записи, параллельная отправка одного сообщения, ответ деканата и уведомления без текста сообщения.

## Настольная и мобильная раскладка

В последнем прогоне сохранены результаты 22 проверок раскладки. Локальный Chromium запускается в отдельном профиле, без открытых пользователем вкладок. Проверка измеряет ширину страницы при 1440, 390 и 320 пикселях и проверяет отсутствие общестраничного горизонтального скролла. Выполняются вход, переходы по нижней панели, переключение даты, фильтрация оценок, открытие профиля, сервисов и студенческого, отправка сообщения касаниями. Для карты проверяются переход из расписания, маршрут с лифтом, смена этажей и масштаб. Прогон сверяет идентификаторы комнат с локальными SVG. Отдельные тесты проверяют маршруты между помещениями и сохранение ссылки при входе. Скриншоты и результат находятся в `var/reports/browser`.

```powershell
$env:DEKA_CHROME_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
.\deka.ps1 test
```

Проверка использует Chrome DevTools Protocol и отдельную тестовую базу. Это эмуляция размеров и касаний, а проверка на физическом устройстве и в Safari остаётся отдельной.

Проверки модели в тестах используют HTTP-имитацию. Для оценки настоящей модели предусмотрены отдельные команды из `apps/portal` с Node.js 26 и конфигурацией установки:

```powershell
node --env-file=../../var/config/application.env tooling/testing/evaluate-assistant.mjs
node --env-file=../../var/config/application.env tooling/testing/benchmark-model.mjs
```

Результаты сохраняются в `var/reports`. Набор из 30 вопросов содержит вопросы о кабинете, отсутствующих сведениях, учебных темах и границах доступа. Проверки по фразам лишь отмечают ответы для просмотра человеком. Они не удостоверяют отсутствие фактических ошибок.

Проверка настоящей MiniCPM прошла без транспортных ошибок. Ручной просмотр обнаружил фактические ошибки в учебном объяснении и перенос пары на соседнюю дату. После этого прямые вопросы о ближайшем расписании, пропусках и готовых справках переведены на ответы из БД. Формулировки и переходы к данным проверяет интеграционный тест. Открытые ответы модели требуют проверки. Подробности: [помощник](assistant.md).

## Восстановление и поставка

`.\deka.ps1 backup-check` создаёт дамп, восстанавливает его в новую отдельную базу и сравнивает контрольные количества записей. Рабочая база не заменяется. JSON-отчёт находится рядом с дампом.

`.\deka.ps1 package` создаёт единый архив исходников с реестром SHA-256. В него не входят var, настройки, база, модель, зависимости и сборки.

## Ограничения проверки

CPU и GPU llama.cpp проверяются реальными запросами отдельно от тестового HTTP-сервера. Конфигурации Compose проверяются синтаксически. Полный запуск Docker Engine, CUDA внутри Docker и команда Docker-резервирования на этом компьютере не подтверждены. Они должны пройти проверку на целевой машине перед передачей в эксплуатацию.
