# Как применяли ИИ при создании Деки

В проекте две разные задачи для ИИ. Codex помогал проектировать, писать и проверять приложение. MiniCPM5-2B отвечает в кабинете и дополняет план подготовки. Масштаб использования оцениваем по следам работы и воспроизводимым проверкам.

## Работа над проектом

| Этап | Постановка и результат | Где проверить |
| --- | --- | --- |
| Дизайн | Владелец выбрал сиреневое оформление по снимкам своего проекта. Codex нашёл сохранённые компоненты и восстановил обзор, расписание и успеваемость. Профиль и сервисы открываются из верхней панели. | `apps/portal/src/lib/application`, `apps/portal/src/lib/modules/overview/ui` |
| Ревизия функций | Codex сравнил версии по сценариям студента и деканата, воспроизвёл ошибки и исправил хранение оценок, импорт, права преподавателя и выпуск справок. | `docs/feature-audit.md`, миграции 009 и 010, `tests/integration/academic-integrity.test.mjs` |
| Переписка | По критерию связи с деканатом Codex добавил двустороннюю переписку в заявлении. Повторы, доступ другого студента и другого факультета проверяются сквозным тестом. | Миграция 011, `tests/integration/request-workflow.test.mjs` |
| Контент | Codex собрал вымышленные учебные сценарии, короткие русские подписи и сообщения состояний. Демонстрационный набор целиком воспроизводится из пустой базы. | `tooling/database/seed.mjs` и `sample-scenario.mjs` |
| Тестирование | Codex добавил проверку на отдельной базе и автоматический прогон в Chromium. Данные участника, файл модели и конфигурация установки исключены из архива. | `tooling/testing/run-tests.mjs`, `tooling/testing/verify-browser.mjs`, `infrastructure/release` |

Модель для разработки и модель кабинета выполняют разные задачи. Мы не используем количество сгенерированных строк как показатель качества. Восстановление дизайна после ошибочной замены оболочки показывает, зачем сравнивать результат с исходным запросом.

## Инструкции агентам

Перед задачей агент получает карту приложения из `docs/architecture.md` и сценарий пользователя. Затем формулирует ожидаемый результат и добавляет проверку там, где возможна регрессия. Настройки установки, дамп и рабочие переписки агентам для воспроизведения не нужны.

Примеры постановок для независимой проверки:

- **Дизайн.** "Сравни обзор, расписание и оценки со снимками Деки. Воспроизведи исходную композицию. Проверь, что сервисы открываются из профиля. Пройди те же страницы с шириной 320 и 390 пикселей, перечисли переполнения и недоступные кнопки".
- **Безопасность.** "На отдельной базе создай обращение студента. Проверь чтение и запись от владельца, соседа по группе, преподавателя и сотрудника другого факультета. Попробуй повторить одно сообщение и проверь, сколько строк и уведомлений сохранилось".
- **Качество ответов.** "Задай локальной модели одинаковые вопросы до и после правок. Сверь оценки, даты и записи с приложением. Отдельно проверь общие вопросы и отсутствие сведений. Сохрани ответы и причины замечаний".

Эти постановки подходят для повторной или независимой работы. Они не служат заявлением о числе задействованных субагентов. Отдельная генерация иллюстраций или дизайн в стороннем сервисе не заявляются. В интерфейсе используются SVG проекта, существующие шрифты и компоненты.

## ИИ в кабинете

**Учебный план.** Сервер выбирает ближайшие аттестации и дисциплины, требующие внимания, из записей текущего студента. Модель может дополнить их короткими шагами. При недоступности модели и при невалидном ответе остаётся план из проверенных данных. Готовность и календарная отметка сохраняются отдельно от текста модели.

**Чат.** Системная инструкция требует краткого ответа на русском, ограничивает утверждения о вузе данными из кабинета и разрешает общие учебные вопросы. Для запроса об оценках сервер передаёт оценку текущего пользователя, для общего вопроса не подгружает личные записи. Текущее время и прямые вопросы о ближайших занятиях, экзамене, готовых справках и пропусках обрабатывает сервер. Модель не изменяет базу и не получает переписки с деканатом. Под ответом указаны разделы, из которых взяты данные или которые вошли в контекст.

**Проверка ошибок.** Набор из 30 вопросов содержит факты кабинета, общие учебные задачи, неизвестные сведения и проверки границ. Ответы модели надо читать: совпадение ключевых слов не доказывает точность. MiniCPM неверно объяснила const и повторила занятие под соседней датой. Серверные ответы по расписанию теперь используют время и аудиторию конкретной записи, не передавая формулировку модели. Для сложных вопросов и советов остаётся ИИ. Подробности в [оценке помощника](assistant.md).

## Воспроизводимость

`deka.ps1 check` и `deka.ps1 test` проверяют проект и изолированную базу. `tooling/testing/evaluate-assistant.mjs` выполняет вопросы через рабочий HTTP API на локальной установке. `tooling/testing/verify-browser.mjs` проверяет настольные и мобильные страницы; запуск описан в [проверках](verification.md). Настоящие ответы, скриншоты и результаты конкретной установки сохраняются в `var/reports`.
