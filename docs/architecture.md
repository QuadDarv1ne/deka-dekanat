# Архитектура

Модульный монолит на SvelteKit. Один сервер приложения и одна PostgreSQL. Модель запускается отдельным процессом или контейнером.

## Папки проекта

| Путь | Ответственность |
| --- | --- |
| `apps/portal/src/routes` | Адреса, загрузка данных, HTTP-обработчики |
| `apps/portal/src/lib/application` | Оболочка, меню, стили, обновление приложения |
| `apps/portal/src/lib/modules` | Прикладные модули |
| `apps/portal/src/lib/shared` | Независимые компоненты, форматирование, валидация |
| `apps/portal/src/lib/server` | PostgreSQL и криптография |
| `apps/portal/src/service-worker` | Кеш только статических ресурсов, отдельная проверка типов |
| `apps/portal/static` | Шрифты, SVG, значки, manifest, offline-страница |
| `apps/portal/tests` | Проверки правил и сквозных сценариев |
| `apps/portal/tooling` | Миграции, начальное наполнение, тестовый запуск, настройки Compose |
| `database/migrations` | Применяемые по порядку SQL-миграции |
| `infrastructure/docker` | Dockerfile, Compose, роли БД, healthcheck |
| `infrastructure/windows` | Подготовка, запуск, остановка, резервное копирование |
| `infrastructure/assistant` | Закреплённая модель, скачивание с проверкой и продолжением загрузки |
| `infrastructure/release` | Единый архив исходников и реестр SHA-256 |
| `var` | Данные конкретной установки, не исходный код |

Внутри `var`: `config`, `postgres`, `models`, `runtime`, `logs`, `run`, `backups`, `reports`, `releases`, `history`. Внутри приложения `.svelte-kit` содержит служебный результат SvelteKit, `.output` серверную сборку, `.test-build` отдельную тестовую сборку, `node_modules` установленные зависимости. Все они игнорируются Git.

## Модули

| Модуль | Назначение |
| --- | --- |
| `auth` | Пароли, серверные сессии, роли, локальный быстрый вход |
| `student-cards` | Выпуск, QR, проверка и экспорт студенческого |
| `academics` | Расписание, результаты, рейтинг, ICS, ручной ввод и импорт |
| `requests` | Заявления, переходы статусов, история, документы, проверка |
| `announcements` | Публикация объявлений факультета |
| `notifications` | Уведомления конкретного пользователя |
| `administration` | Просмотр учётных записей, реестр студентов и аудит |
| `overview` | Сводка из других модулей |
| `assistant` | Чаты, доступный контекст, модель и системные часы |
| `study-plan` | Аттестации, приоритеты подготовки и отметки готовности |
| `campus` | Поэтажная схема, сопоставление аудиторий и маршруты по графу |

## Внутри модуля

`*.types.ts` описывает контракты; `*.labels.ts` подписи; `*.policy.ts` правила; `server/*.repository.server.ts` чтение; `server/*.service.server.ts` изменение данных; `ui/*.svelte` интерфейс. Все серверные файлы имеют суффикс `.server.ts`. Импорты `#modules`, `#shared`, `#server`, `#application` определены в пакете приложения.

Маршрут проверяет роль, разбирает запрос и вызывает модуль. SQL в маршрутах запрещён. Общие компоненты не зависят от прикладных модулей. Страницы не получают пароли, токены и параметры подключения.

Изменение заявления, история, аудит и уведомление сохраняются одной транзакцией. Учебные изменения сериализуются транзакционной блокировкой. Редактирование расписания проверяет версию записи и пересечения группы, преподавателя и аудитории. Подтверждение импорта повторно проверяет полномочия и либо записывает весь файл, либо откатывает изменения. Повторное подтверждение завершённого импорта не дублирует записи.

Оценка содержит версию; сохранение устаревшего значения отклоняется. История сохраняет предыдущий и новый балл вместе с автором и источником изменения. Импорт фиксирует версии на предпросмотре и сверяет их при подтверждении. Отменённая пара не занимает уникальное время группы; восстановление повторно проверяет пересечения.

Готовность общего обращения не выпускает справку. Проверяемый документ создаётся только для предусмотренных видов справок. Роль приложения может добавлять аудит и историю, но не менять и удалять события.

Переписка хранится отдельно от смены статусов. Права повторно проверяются при чтении и записи. Сообщение и уведомления создаются в одной транзакции. Уведомление содержит ссылку на переписку без текста сообщения. Роль приложения может добавлять сообщения и читать их; SQL и выдача данных ограничены владельцем обращения и деканатом его факультета.

QR студенческого содержит случайную ссылку, без ФИО и учебных данных. Проверяющий должен войти в систему. Для преподавателя дополнительно проверяется закрепление группы, для деканата факультет. Заблокированная учётная запись не проходит проверку. Ссылка не заменяет университетскую подпись или интеграцию с системой прохода.

Модель не исполняет команды, SQL или сетевые запросы из текста ответа. Общие учебные вопросы разрешены. Вопросы о текущем времени обрабатываются серверными часами до обращения к модели.

Корневой `deka.ps1` только направляет команды. Запуск контейнеров находится в `infrastructure/docker/start.ps1`, выбор GPU и резервный CPU в `assistant-runtime.ps1` соответствующей платформы. Файлы Compose отдельно описывают CPU, CUDA и Vulkan. Сервис `model-init` подготавливает проверенный GGUF до сервера модели. Все имена файлов, папок и архивов используют ASCII.

Границы проверяются автоматически в `apps/portal/tests`. Применённые SQL-миграции не редактируются. Seed при запуске не выполняется.
